# Roadmap

**Context for every session. Do not build ahead.** Only the phase named in your task is in scope. Later phases are listed so today's architecture leaves room for them.

## Purpose

A free, browser-based tool that helps a complete beginner understand what they see on a cruising yacht:

- what each rope and control does;
- how the sheets and sails react to the wind;
- what the terms are, in English and Russian;
- typical problems and their fixes.

The reference boat is a **Hanse 508**. The tool favours clarity over realism.

## Architecture hooks to keep from Phase 1 onwards

- **IDs everywhere.** Every mesh and rope maps to an id in `content/registry/parts.json`; a rope's UI control uses its rope's id. Phase 4 hangs its content on these ids.
- **Pure model.** `src/model` has no DOM and no three.js. `step(state, dt)` already takes boat velocity and heading (zero in Phase 1).
- **Data-driven boat and sails.** Geometry, ropes, controls and optional sails (gennaker `enabled: false`) come from `content/boat/hanse508.json`. A second boat later means a second data file, not new code paths. This includes the cockpit: clutch banks, labels, which rope goes to which winch, the winches (count, power ratios), the stations and Realistic mode's values. No Hanse names or positions in code; the 3D model is built from the data file, so a similar boat needs only new numbers. Load the boat file by id (`hanse508`) so a chooser can be added later.
- **Time and pause.** `step(state, dt)` gets `dt = 0` while paused; nothing reads wall-clock time directly. The time bar (M10) only scales `dt`. The on-board clock (Phase 3) is a start date-time plus the simulated time; the start is part of the state and the link, and the real clock is read once, only when the user picks "now".
- **i18n from day one.** UI strings through `t()`. Names come from the registry by language code. Adding a language means adding data.
- **Sailing areas as data** (owner, 2026-10-12). From Phase 3 the place the boat sails in is a data file loaded by id, as the boat is: name, latitude and longitude, time zone (for sunrise, sunset and the clock), later local winds, waters and marks. The Adriatic is the default and the only area at first; more training areas later mean more data files and a chooser, not new code paths. No Adriatic names or numbers in code.
- **Verifiable content.** Sailing claims carry a source and a status (`docs/PHYSICS_TRUTHS.md`, registry `status` and `sources`). Phase 4 can show "unverified" markers.
- **Shareable state.** The URL reproduces what the user sees. Use it for bug reports and later for exercise links.
- **Modes and sections** (owner, 2026-10-14; built in Phase 5). From Phase 5 every panel block is a *section* with an id, and a *mode* (Learn, Easy, Realistic, later Harbour and Exercises) is data: which sections show, in what order, open or folded, on a phone and on a desktop. Later phases add sections and mode entries, not new tabs. The mode and the sheet's height are UI state; `src/model` does not know about them.
- **Phone first, desktop richer** (owner, 2026-10-14). Everything works on a phone; a desktop may show more at once. A feature that cannot be comfortable on a phone is reduced there (one block at a time, full-height sheet), never removed.
