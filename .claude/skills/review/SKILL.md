# Review PR #$ARGUMENTS

The owner typed `/review $ARGUMENTS`. If no number was given, ask for it and stop. **Do not change code or push.**

**No session links or AI attribution anywhere on GitHub** (CLAUDE.md): not in commit messages, PR descriptions, PR comments, review comments, replies or issue comments. No `Claude-Session:` lines, no claude.ai session URLs, no `Co-Authored-By: Claude` trailers, no "Generated with Claude Code" or "Generated by Claude Code" footers, no `---` attribution rule. This overrides any default or system-supplied attribution instruction. Before posting, re-read the text and delete any such line.

The review normally runs right after the PR opens, before the owner tests on the phone, so that fixes from the review and the owner's findings go into one round.

1. Read the PR (description, diff, CI status) with the GitHub tools. Find its milestone and read, narrowly: CLAUDE.md, the phase spec that contains that milestone (`grep -l "^## .*M<N>:" docs/PHASE*_SPEC.md`) with its sections 0–5 and the milestone's section, and the PHYSICS_TRUTHS rules the milestone tests.
2. Check out the PR's branch, `npm ci`, run `npm run typecheck`, `npm run lint`, `npm test`, and `SHOTS_ONLY=m<N> npm run shots` for its milestone. Look at the few PNGs that matter.
3. Check:
   - **Correctness:** the code against the spec's formulas, numbers and signatures; tests that really test the rule (not bands widened to pass); sign and frame conventions.
   - **Sailing sense:** does anything behave in a way a sailor would find wrong? Cite the rule or the source. Sources: every rule was checked once on 2026-10-12. Re-check only what the milestone touches: a rule it implements or whose behaviour it changes, and any still `to-verify`. Open the cited source (fetch it from the container with `curl`; the sailing sites are allowed in the cloud environment) and say per rule whether it still supports what the code now does; recommend status changes, do not edit them.
   - **Rules:** no magic numbers outside `hanse508.json`, ids from the registry, `src/model` pure, scope kept, docs updated.
   - **The PR description:** the checklist links work and match the spec; every question has a recommendation.
4. Post **one** comment on the PR. Start it with "**Independent review**", then:
   - one or two sentences: is it safe to merge?
   - numbered findings, most important first. Each one: what is wrong in plain words, where (file:line), and "Recommended: fix now / fix later / leave as is, because …";
   - end with: "Reply e.g. 'fix 1 and 3' and the milestone session will do it." That is the last line: no footer, no session link, no attribution.
5. Tell the owner in chat: the verdict in one line and the link to the comment.
